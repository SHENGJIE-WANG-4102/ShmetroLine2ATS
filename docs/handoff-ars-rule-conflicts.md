# 任务：两条规则互相抵消造成的停车/紧急制动，及其复现压测

用户在桌面版连续运行到第二天，遇到两次：09:30 机场方向一串「等待进路」，17:43 龙阳路 026-回段 ↔ 034-1260 死锁。没有留诊断文件。用户要求系统性解决，不要再一个现场加一条规则。

## 已经查到的事实

先跑了两组压测，都没有出事：
- 第一天带随机故障 22 例；
- 每 10–20 分钟让一列西行车在龙阳路终到、回龙阳路库，8 例。

后来加上第二天和天气（07:00 起 5 小时、15:00 起 4 小时，大风加暴雨），12 例里有 4 例失败。归成两个根因。复现材料都在 `work/deadlock/`：

- `day2w.ts`：第一天全天 → 换日 → 第二天，带天气，可选强制回段。
  - 运行：`npx tsx work/deadlock/day2w.ts <故障等级> <种子> <风级1-4> <回段间隔分钟,0=不加>`
  - 遇到第一条完整性违例就停，同时导出诊断。
- `look.ts` / `look2.ts`：用诊断文件里的 `state` 还原现场，打印卡住的车和它的等待链。
- `who2.ts`：从切换时刻回放，逐步追踪 S2914 的进路状态和 002 的 desire。
- 四个失败现场：`d2w-2-4-2-0-day2.json`、`d2w-2-4-2-20-day2.json`、`d2w-3-5-1-20-day1.json`、`d2w-2-5-3-20-day2.json`。

### 根因 A：停在停车点前，ATO 不起步，ATS 也不排进路

**现场**：
- `010-1003`，第二天 07:16。
- `064-1247`，第一天 17:49，3 级故障。说明不只是跨日才有。
- 两车都停在浦东机场下行站台，离停车点差 5.6–5.7 m，速度 0。
- 移动授权约 11.7 m，结束在出站信号 X3105 前，而这时 X3105 还没有进路。
- 起因：湿轨或大风限速下进站，触发了超速紧急制动，停车点没对上。

**两条规则怎么互相卡住**：
- `src/sim/movement.ts:652`：`maCode === 'ROUTE_WAIT' && maDist < 15` 时 `vT = 0`。本意是不要往红灯前几米的短授权里起步，但它没看停车点就在这段授权以内。
- `trainDesire` 认为车会在信号前停站（`stopDist < nextSignalDist`），所以不排前方进路。
- 结果：车不动，进路不来，5 分钟后报 LIVENESS，后续车全部排队。用户在机场看到的那串「等待进路」很可能就是这个。
- halt 显示的也是「等待进路」，把真正原因藏起来了。

### 根因 B：让行规则取消了被让那列车的进路

**现场**：`d2w-2-5-3-20-day2.json`，第二天 08:00。川沙出段的 `002-定位` 站在共用出入段线 G2918 上，离 S2914 6 m。

**时间线**（`who2.ts` 回放结果）：
- 07:59:45，ATS 为 002 排好 S2914→S2906。
- 07:59:46，这条进路被取消，接近锁闭延时 30 s。
- 08:00:17，进路重排，002 拿到 109 m 授权起步。
- 08:00:18，进路又被取消。这时 002 只有 0.3 m/s，不算接近锁闭，进路立即解锁。授权当场收回，002 紧急制动，并报 `MA_NO_ROUTE` 安全违例。

**取消的人**：后面的 `024-回段`。它命中了 `src/sim/ats.ts:1403-1410` 那条 D82「回段车让出段换端车先出」：
```ts
const active=sg.route>=0?sim.routes.get(sg.route):undefined;
if (active && !active.entered && !active.manual) cancelRoute(sim,sig);
```
它取消的是自己面前信号机上的进路，没检查这条进路是给谁排的。这里那条进路正是被让的 002 的出段进路。让行规则把它要让的车挡住了。

## 要做的事

### 1. 根因 A：改这条规则本身，不加新例外

- `movement.ts:652` 的「短授权不起步」只在前方目标就是授权终点时生效。停车点在授权以内（`scan.stopDist <= scan.maDist`）时，目标是停车点，照常起步、精确对标。
- 再查一遍 `halt.ts` 的停车原因归类：这种「授权够、停车点没到、车却不动」的情况，不能再报成「等待进路」。

### 2. 根因 B：立一条不变量，ATS 不许取消给别的车排的进路

- **记下进路是给谁排的。** `ActiveRoute` 现在只有 `owner`，要等车过了始端信号才写。新增一个字段，记录 ARS 是为哪列车排的这条进路。`trySetRoute` 已经有 `opts.train`，直接存下来。如果换日时 `carryWorld` 要搬它，在 `DAY_STATE` 或 routes 的搬运里一并处理。
- **把 ARS 取消进路的入口收成一个函数。** 列出 `ats.ts` 里所有 `cancelRoute` 调用（356、1229、1272、1308、1407、1556、2464 行附近，以你看到的为准），各自归类：
  - 取消自己的旧进路：可以；
  - 取消空闲自动进路（fleeting、没人接近）：可以；
  - 取消为别的车排的进路：一律不许。只能让自己这列车不排，并用 `setArsWait` 写明在等哪列车。
  - 1407 那条改成：只撤销为自己排的进路；如果 S2914 上是被让车的进路，就什么都不碰，自己等着。
- **加一条完整性检查**（`src/sim/invariants.ts`）：ARS 取消了为另一列车排的进路时，立刻记一条违例，写明是哪两列车、哪个信号机。以后再有规则互相抵消，会在发生那一刻报出来，不会等到 5 分钟后才变成死锁或 LIVENESS。人工调度命令和故障处置可以取消，不算违例，但要能区分来源。

### 3. 把压测探针变成可以反复用的工具

- 把 `work/deadlock/day2w.ts` 整理成 `scripts/stress-day2.ts`，参数保留：故障等级、种子、风级、强制回段间隔。强制回段的选车条件写成参数，不要写死站名，按 AGENTS 硬规矩 7 用方向辅助函数。
- 以后跨日、天气、回段相关的改动，都用它跑一小批。

### 4. 修完后再查龙阳路死锁

- 用户那次的龙阳路死锁（026-回段 ↔ 034-1260，17:43）还没复现出来。
- A、B 修完后，用新脚本再扫一批：至少 16 例，覆盖风级 1–3、故障等级 2/3、强制回段间隔 0/15/20。
