# 任务：连续运行，跨运营日不重开

## 背景

现在到 03:45 运营日切换时，`worker.ts` 会调用 `start(nextOperatingConfig(sim))`，**整个仿真重新建一遍**。只有各段的车数（`depotStock`）被带过去，其余全部重置：
- 还在跑的列车被收掉（`unfinishedAtRollover` 只记一条日志）；
- 车场里的车号、正线存车位上的车号都重新发；
- 封锁、故障、进路状态全部丢失；
- 加开车要到 27:45 以后才结束时，排图会提示「会被收掉」（`planning.ts:116`）；
- 夜间测试这类跨 03:45 的场景没法做。

**用户决定**：连续运行是最基本的要求。数据积累拖慢速度要靠清理旧数据解决，不能靠重开。

## 目标

时间一直往前走，世界不重开。「运营日」只是根据时刻算出来的标签。到切换点只做这几件事：
1. 生成新一天的运行图，接到现有计划后面；
2. 上一天的诊断归档；
3. 按天统计的指标和考核清零；
4. 生成新一天的随机故障、教员事件和夜间封锁。

列车、车号、正线存车、封锁、故障、进路都原样继续。

## 要做的

### 1. 时间

- `sim.t` 不再回绕。在 `dayRandom.ts`（`OPERATING_DAY` 所在的文件）里写一处换算：
  - 由 `t` 算出第几个运营日；
  - 由 `t` 算出当天时刻，范围 [4h, 27.75h)。
- 找出所有拿 `t` 当钟点用的地方，统一改成用当天时刻：客流曲线、高峰时段（`PEAK_SECTION`）、首末班、封锁窗口、随机故障和教员事件的时间窗、PIS、运行图里的固定时刻等。动手前先 grep 一遍，把找到的位置列在汇报里。
- 新一天的运行图仍然按当天时刻生成，接到计划里时整体加上这一天的偏移（运营日序号 × 86400）。显示时间已经按 24 小时取余，复核一遍就行。

### 2. 切换（替代 `start(nextOperatingConfig)`）

- 在原地更新 `sim.config`：日期、日型、种子 +1。`nextOperatingConfig` 里的内容合并进这一步。
- 新运行图的 `PlanContext` 用**实际状态**生成：
  - 各段库存：现在停在车场里的车，加上会在新一天第一趟出段前回到车场的车；
  - 正线存车：现在实际停在各存车位上的车。
- 去掉 `initialDepotStock` 里「凑满 100 列」的补车。车辆不再凭空出现，也不会凭空消失。
- 新运行图的追加，复用加开已有的机制：`planning.ts` 里车次、车底的 id 本来就是在原计划后面顺延的。
- 新运行图里有车底要从某个正线存车位出车，但那个位置没有车（比如原定停进去的车退出服务了），按「失去车底」处理：走现有的热备、备车接替（D70 R3）。处理不了就取消，记日志写明原因。不许凭空变出一辆车。
- 跨切换点还在跑的车，继续执行它原来的任务。
- 删掉 `planning.ts:116` 的「会被收掉」提示，以及 `unfinishedAtRollover` 的收车逻辑。如果还要提醒「切换时有车不在过夜位」，改成一条普通信息日志。
- 归档（`dayArchive`）保留，只是不再紧接着重建仿真。

### 3. 数据增长

- 归档后，清掉已经结束的旧数据：
  - 前一天已经跑完的车次和车底；
  - 列车历史轨迹里过期的部分；
  - 事件和日志。
- 清理时，凡是保存车次或车底 id 的地方都要一起改，不能留下指向已删除数据的 id。先列出这些地方，再动手。
- 如果改 id 的风险太大，可以只清事件、日志、轨迹这些不含 id 的部分，车次、车底先留着。但要量出每天大概增长多少，写进汇报。

### 4. 存档

- 旧存档（单日、`t` 在一天之内）要能直接读。
- 新存档读回来以后，时间、计划、车号要和存档前一致。

## 完成标准

1. 只运行一天时结果不变：两种日型运行图的 `trips`、`blocks` 哈希和改前一致，`validate-plan` 0 error，首末班脚本和改前一致。
2. 跨切换测试：从 26:30 开局，跑到第二天 05:30（约 3 小时仿真时间）。
   - 跨切换前后，所有列车的 id、车号、位置连续，不消失；
   - 车场每股道的车号在 03:45 前后完全一致；
   - 一列 27:30 出发的加开车（或夜间测试车）跨过切换点，正常跑完；
   - 第二天出段的车，从它实际停着的段和股道出来。
3. 增长测试：不跑物理，直接连续调用 3 次切换函数，比较每次之后计划、事件、日志的规模。清掉的部分不再增长；没清的部分写出每天增长多少。
4. 存档测试：跨切换后存档再读档，状态一致；读一份旧的单日存档不报错。
5. `npx tsc --noEmit` 通过；`tests/dispatcher.test.ts`、`tests/timetable.test.ts` 和新测试都通过。

## 不要做

- 不改运行图的生成规则和时刻。
- 不靠重开仿真来解决任何问题。
- 不跑 `npm test`、soak、simday。多天的长跑由用户在 120× 下自己测。

## 用户在 120× 下看什么

- 23:00 后加开一列跑到 04:00 的车，看它跨过 03:45 后是否还在。
- 03:45 前后车场图的车号是否一致。
- 第二天连续跑一整天，看速度有没有明显变慢。如果变慢了，告诉我是在第几天、跑到几点开始的。

## 和检修任务的关系

检修任务（`docs/handoff-maintenance.md`）排在这个任务之后。世界不重开以后，车号天然连续，检修那边只需要车辆档案和派车规则。
