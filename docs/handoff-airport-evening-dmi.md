## 1. 工作日 20:30 前后机场有开往淞虹路的车

现象：
- 实拍（10/21，周三）：机场往西 20:31 开往蟠祥路，20:33 开往淞虹路，20:37 开往蟠祥路。
- 模型：20:10:58（4208）之后，开往淞虹路的车要到 21:07:24（4226）才有，中间全开往蟠祥路。

要求：
- 先查清楚现在机场开往淞虹路的车是怎么来的：小交路？回北翟路基地的车顺带载客？还是别的规则？为什么 20:10 有一班，之后断档到 21:07？
- 改规则或数据本身，让这班车作为规则的结果自然出现。不许单插一班来对上这张照片（AGENTS 硬规矩 2）。
- 只有一张照片，不要据此改整个晚间的交路比例。如果规则改动会牵连别的时段，列出受影响的车次，说明为什么合理。
- 别的证据不能被打破：10/16 淞虹路的实拍显示，20:46–20:55 淞虹路的终到车都是广兰路始发（`docs/field-2026-10-16-pis.md`）。
- 规则本身找不到依据的，按 AGENTS 给我出选择题，不要硬改。

验收：
- 工作日计划里，机场往西在 20:25–20:40 之间至少有一班开往淞虹路，前后都有开往蟠祥路的车。
- validate-plan 两种日型 0 error。
- firstlast 不变。
- gaode-compare 不合格格数不增加，可信列不变差。
- D 条目写清规则和依据。

## 2. DMI 按 10/21 实拍改版

`src/ui/dmi.ts` 原来是按模糊照片画的。和新照片（`reference/dmi/IMG_20261021_202812.HEIC`，读数见 field 文档）对照，至少要改这些：

- **顶栏**：
  - 改成下一站在左、终点站在右，标签在上、站名在下；
  - 去掉单独的「车次」栏，实拍没有这一栏；
  - 依次显示状态（扣车时显示「HOLD」）、`T` 号、表号、灰框「C000」、白按钮「菜单」。
- **站名简写**：
  - 到站折返时，站名后加「折」；
  - DMI 用的站名简写写成车站数据里的一个字段，不要在代码里按站名替换。照片里只有「浦东1_2航站楼」这一个实例，别的站不知道怎么简写的，就照原名显示，在 README 的 DMI 小节里注明。
- **DEP**：放在顶栏下方。
- **表盘**：每 20 km/h 标一个数字。
- **底部**：圆圈 B 图标加「模式-级别」文字（如 DTO-CBTC）；底行是日期、时间、「版本：1.0.0」。
- **消息栏**：用实拍里的说法，如「ATPM模式可用」「定位已确认」，对应模型里已有的事件，不要新造事件。

照片里看不清或不知道含义的元素（C000、两个黄色竖条、「--m」距离条），按看到的样子画出来，在 README DMI 小节里标「含义未知」，不要猜着接数据。

验收：`npx tsc --noEmit`；用 `npm run app:build` 打包后，截一张跟踪列车时的 DMI 图，和实拍放在一起对比，图放在 `work/`。
