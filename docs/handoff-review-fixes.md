## 2. 晚间机场断档：先列数据，不改规则

工作日计划里，22:25 到 23:31 之间没有一班载客车开到机场；同一时段，远东大道有十几班终到，再回川沙停车场。

## 3. 运营日切换的「未到过夜位」误报

- `unfinishedAtRollover` 拿列车位置和 `overnightPlaces` 的 `arrivalBerth` 比较。工作日 seed 3 在 04:00 开局时，8 列正线过夜车里有 6 列被判成未到位（探针 `work/probe/rollover.ts`）。这样每次切换都会报出一串假警告。
- 改成：凡是列车已经完成当天任务、静止在任何一个合法的过夜或存车位置（包括出发用的站台泊位），就不算未到位。判断「合法过夜位」要复用现成的函数，不要另写一套。
- 加测试：开局时列表为空；人为让一列车在区间里运行，列表里有它。

## 4. 前后接续的教员事件被拆散了

- 「大风黄色预警 → 暴雨 → 阵风≥10级 → 风力减弱」原本是同一个场景里的先后步骤，现在被拆成四个各自随机的事件。比如「风力减弱（黄色）」可能在根本没刮风的时候单独发生。
- 前后接续的步骤合成一个事件，内部按原来的相对时间依次执行，例如「大风过程」。其他场景照这个原则逐个检查：
  - 依赖前一步状态的，合并；
  - 能独立成立的，单列，比如大客流、道岔失表。
- 事件 id 改成能看出内容的名字。现在的 `rmg-surge-2` 实际是「列车乘客紧急报警」，id 和内容对不上。

## 5. 车尾不跟道岔走（D104 的图形）

- 用户截图：003-4012 从广兰路中间股道往西出站。车头已经上了上行正线，图上整条车都画在正线上，车尾没有沿真实占用的路径经过道岔回到中间股道。

## 6. 金科路报站英文被切断

- 用户反映金科路报站没有英文。录音素材是好的：
  - 「下一站」切片 `original-next-up-jkl` 的英文在原录音 33.1–37.5 s；
  - 「到站」切片的英文在 114.4–118.4 s；
  - 渲染出来的 mp3 里，英文段响度 -16.9 LUFS，和中文段一样。
- 怀疑是播放中途被 `src/ui/onboardaudio.ts` 里的 `invalid` 判定淡出了。比如从广兰路中间股道出发后，`frame.doorSide` 或终点变化导致 `target !== call`，或者 `willStop` 短暂变为 false。
- 用规划器级别的测试复现：一列 CM 车从广兰路往西开到金科路，逐帧喂入，断言「下一站」和「到站」两段都完整播完，没有中途 stop。找到根因再修。正在播的这一段不应该因为与这次报站无关的字段变化而被切断。
