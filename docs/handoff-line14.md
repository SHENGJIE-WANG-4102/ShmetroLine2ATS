## 3. UTO

这一节全部是公共代码，按 `line14-core-interfaces.md` 的口径写。

- **入口**：
  - `LineData.unattended` 和 `current.ts` 的 `unattended(task)` 判据；2号线和测试线四项全填 `false`。
  - UTO 流程写成独立函数，只在少数调用点按判据分流，不在现有门控逻辑里逐行插判断。
- **doorClose**：
  - 到点自动关门、自动发车，没有司机按钮这一步；
  - 自动关门前的提示和等待时间【假设】。
- **turnback**：
  - 无人折返、自动换端；
  - 换端耗时【假设】。2号线的 `atoEndChange` 是有司机的口径，14号线另给数据。
- **wakeSleep**：
  - 列车状态机：休眠 → 唤醒（上电、升弓、自检）→ 可用；收车后清客确认 → 休眠；
  - 首班前提前多久唤醒、各步耗时【假设】；
  - ATS 上要能看到列车处在哪个状态。
- **自动洗车**：
  - 回段后部分列车先洗车再休眠。基地内部没有建模，做成在段内的一段作业时间，在 ATS 和段内状态里可见；
  - 哪些车洗、每次多久【假设】。
- **depotMoves**：
  - 自动出段、入段的列车状态部分现在就做；
  - `ats.ts` 里的出入段进路和资源仲裁（`trainDesire`、`reversalGuard`、`depotEntryBlocker`、`resolveDepot`、`spawnDue`）**等 D142**，见第 6 节第 5 步。
- **随车人员接管（ATPM / RM）**：做成一串操作，玩家用 `sim.command` 下命令，电脑控制的车也走同一串。步骤见 `line14-decisions.md`「FAM 转 RM 的操作步骤」：
  1. 报 OCC；
  2. 插钥匙；
  3. FAM 开关拨到 0 位；
  4. 手柄拉到制动；
  5. 等 RM 或 ATPM 灯亮，按按钮确认；
  6. 人工驾驶，必要时对标；
  7. 按需开关门；
  8. 报 OCC，申请升回 FAM；
  9. 双手柄归 0，FAM 开关拨回全自动位。

  要求：
  - 先关门再操作，所以会增加停站时间；
  - ATPM 要 CBTC 正常才能进；
  - 各步耗时【假设】。
- **随机接管**：每天随机挑几列电脑控制的车，接管一段 ATPM 再恢复 FAM。列数和时长【假设】，写成数据。
- **UTO 故障**：在 14号线 `randomFaults` 里加一种车载故障，仿照 `trainDto`：
  - 降级 ATPM，由随车人员开；
  - 远程复位成功就恢复 FAM，失败就开到终点或回段；
  - 远程复位是调度命令，走 `sim.command`，成功率和耗时【假设】。
- **进站冲标**：
  - 复用 `ats.ts` 的 `atoOverrun`，加一个和天气无关的随机触发，写成线路数据，2号线填 0；
  - 全年随机，和季节无关（用户确认）；
  - 14号线上由随车人员请求退行，转 RM，按 `OPERATIONS.reverseKmh` 退回对标。
- **CBTC 失效**：
  - `onLoss: 'restrictedManual'`，复用 RM 模式和 `PERF.vRM`，由随车人员驾驶；
  - 2号线填 `'fallback'`，测试线填 `'wait'`（把原来的占位规则变成测试线自己的数据）。
- **对讲和日志**：14号线上报话的人写「随车人员」，不写「司机」，这些文字放进线路数据。
- **停车原因**：halt 和 arsWait 里要写清实际在等什么：在唤醒、在洗车、在等 OCC 确认、在插钥匙……
