# 14号线设计决定

## L14-01 线路数据独立、配线逐站6倍复核（2026-10-24）

用户决定：14号线独立建数据，不展开、继承2号线。站序、里程、站台和配线以全网配线V2025.26.2为准；上行往封浜、下行往桂桥路；龙居路建成未开通，45km/h通过；49列14A01、185.6米、8节；正线全地下，CBTC主用且无后备，常态FAM，失联由随车人员转RM；英文Road写全，先不显示终点代码，只显示14加三位表号。音频空库，换乘末班表留空。两端首末班和节日豫园封站以官方资料为准。

配线复核：PyMuPDF 6倍逐站渲染31张并目视读图，道岔站另扩框。结果写回 `reference/line14/line14-layout-pdf.md`，只纠正初读。确认曹杨路是两端接正线的中间存车线、一岛一侧；武宁路与武定路是岛式，纠正初读“侧式”；黄陂南路和源深路两侧式，各一条中间存车线。真新新村站西、蓝天路站东各两条中间折返线，近端双Y交叉、远端各回正线并有短车挡。封浜、桂桥路都是两条出入段线，不把它们画成独立中间双线组。

用户决定：曹杨、黄陂、源深各一列正线过夜，白天作热备；真新、蓝天一条线折返，第二线按容量放热备；两个基地出来的折返线不放热备。联络线按PDF画，正常营业不排走。通用 `PairStubDef.link` 复用现有存车线连接构建器，为两条中间线补远端连接；远端道岔前停车，短缓冲段不是列位。`SidingDef.purpose: 'interline'` 不登记任何泊位，避免联络线被当热备。双端中间线各登记一列容量。

线路色从PDF矢量绘图对象读得RGB98/96/32（#626020），不是从其他线路复制。核心独立文件：`src/data/lines/line14/line14.ts`、`firstlast.ts`、`physics.ts`、`ui.ts`。6倍中间图片和探针在忽略目录 `work/line14-pdf/`。

本组公共文件：`src/data/types.ts`（可选连接/用途/编组字段，由接口组汇总）、`src/sim/topology.ts`（通用双端中间折返线、联络线无泊位）。2号线没有这些可选字段，构图节点/进路顺序保持原路径。`tests/line14-layout.test.ts` 验证两端进入折返线、足够有效长度、三处存车各一位、联络线无泊位、所有轨段有计轴分区和双基地出入路径。

## L14-02 官方首末班的统一走行/独立站表预算（2026-10-24）

用户决定：不改单趟时刻、不加删车对格；用本线物理最短走行、停站与每停站区间统一固定富余。官方表原样保留30站×4列（120格），首末终点“到达”按到达检查，不混为发车；West/East映射封浜/桂桥，lastBig/lastLate均指全程末班。

【假设】增通用可选 `simulation.calibration.dwellModel: 'station'`。14号线图定停站直接读其 `STATIONS.dwell`，乘当时图定系数；缺省仍走原客流停站模型，2号线和测试线不启用，原算术不变。两日型全日停站系数均1、物理停站下限20秒；不设方向/单趟/时段特例。

反推方法：先用本线8A和PDF里程算物理最短走行，统一富余约束0～45秒，普通站停站约束20～35秒、换乘站30～60秒；线性规划最小化120锚点的最大绝对差。连续解统一富余15.925秒、最大误差36.95秒。为避免模型精度冒充实测，富余取16秒，站表停站取5秒粒度。复用实际 `computeRunTimes` / `buildStops` 的0.1秒截断后，两日型各120格：**最大绝对误差42.3秒，0格超过60秒，每日49格不同floor分钟**。不宣称120格全对到分钟。

最小矛盾证据：同一静态走停预算下，桂桥路首05:30、末22:30恰差17小时，所以乐秀路两个时刻也必恰差17小时；官方乐秀往封浜首06:34、末23:35相差17小时01分，两个floor分钟窗无交集。若只放开首末统一停站倍率，乐秀这两格要求末班累计停站变长，武宁往封浜首06:13/末23:12两格却要求末班变短；同一个倍率不可能同时满足。该四格矛盾只针对静态/统一倍率模型，不声称任意复杂时段函数都不可解。没有真实停站/时段资料，不为120格编按钟点例外。

`tests/line14-official-time.test.ts` 对两日型240项逐项保持绝对误差≤60秒，并逐格打印分钟不同清单；没有降低或豁免原有完整性检查。求解输入、脚本、全部差值和解释在 `work/line14-official-fit.md` 及同目录 `line14-fit-*.json`。

本组公共文件：`src/data/simulationExtras.ts`（可选停站模型）、`src/sim/calibration.ts`（一个模型入口）；14号线自己的 `simulation.ts` 只改停站/校准数据。

## L14-03 固定大小交路、区段窗口与三处实车过夜（2026-10-24）

用户决定：工作日大小交路1:1，真新新村—蓝天路，双休日全程单交路；任何已铺画客运请求不得靠取消、截短或延长终点解决冲突。14号线使用通用可选 timetable.reference（大世界、按核心区段中部选取）、preserveRevenueRoutes 和 positioningRevenue:false；核心参考时刻两方向相同，早峰间隔仍独立从唯一HEADWAYS派生。全部出入段定位保留拟合的走停时刻，但不载客；不把空送计成额外大交路。

固定区段窗口验收：各官方区段自动取里程几何中心最近的营业站作为共同测点，两方向使用同一测点；取窗口内可登乘发车数，目标为窗口长度/官方间隔四舍五入，逐格容差±1列。测点不按结果挑选。工作日14格、双休日2格，结果由 tests/line14-timetable.test.ts 输出。分钟表、测点车数各自核验，不互相替代。

三处过夜仍由 overnightPlaces/overnightHolds/storageOccupancy 统一建模。新增可选 preserveService 表示：从物理存车位空送接续一个原有任务；收车后从实际终点另排空车入位，不把客运短交路截在中间站。源端只使用一次真实泊位，首班/末班发布锚点不可由过夜车代替基地出车。两端首班明确从各自基地05:30发出。存车位方向用现有 storageArrivalBerth 取得同一条线的相应朝向，不能另造泊位。回归同时检查每天三处各一列稳定起点/终点。
