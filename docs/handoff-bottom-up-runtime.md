### 2. 每个区间的「现场 − 物理最短」

物理最短 = 用现有车辆性能、限速、坡度，1 级、无富余、无调速（复用 `computeRunTimes` 那套，不另写）。对每个有现场数据的区间算：

- 现场 − 物理最短（秒和百分比）；
- 同一时段（白天等级 1、21:10 后各级）分开。

然后看分布：如果大部分区间都在一个小比例附近（比如 3%~8%），少数几段明显偏大或者现场比物理最短还快，那么：
- 偏大的：到配线图（`reference/上海轨道交通全网配线V2025.26.2.pdf`）、线路资料里找物理原因：急弯、道岔侧向、桥、站间特殊线形；找到就写成「某处限速 X km/h【假设】，依据……」，并用模型算加上这个限速后该区间的物理最短变成多少。找不到就列「解释不了」。
- 现场比物理最短还快的：说明模型的限速、坡度或车辆性能本身就太保守，列出来。

不许为了凑现场，给某个区间单独设一个「区间速度」或补差秒数。

### 3. 停站

按门声口径，每个站次的现场停站和模型停站对比，分时段。看是全线统一偏长或偏短，还是少数几个大站长（换乘站、客流大的站）。给出停站规则的改法建议（规则，不是逐站表；真实存在的大站差别可以写成站的属性数据，要写依据）。

### 4. 合起来对官方首末班

两个方向，用「物理最短（加上第 2 步找到的有依据的限速）× (1 + m) + 停站（第 3 步建议）」算全程，对官方首末班的端到端时间（`src/data/firstlast.ts`，注意官方只到分钟）。

- 求出能对上官方全程的统一富余 m，白天和夜间各一个。
- 给出用这个 m 以后，每个有录音的区间的残差表。残差大的就是还没找到的物理原因。
- 白天高架长区间（远东大道↔海天三路、广兰路↔唐镇、海天三路↔机场）按这套算法巡航会跑多快，对用户观察「白天约 80、晚上约 60」。
