# 任务：10/22 晚试玩五个问题（先做这个，再做 handoff-bottom-up-runtime）

## 1. CM 过标 1.69 m，换向器打后、P4，车不动

现场（用户截图，21:17 版 exe）：071-1044，上行海天三路，CM-CBTC，过标 1.69 m，DMI 已出「过标停车，司机退行对标」；换向器后、手柄 P4，速度一直 0，界面上看不到为什么不让退。

我读代码的推测（未复现，你先复现再定）：`reversePermission`（`src/sim/movement.ts:606`）要求退行后的整列车身都在 `tr.recentBody` 里、并且 `moveBack` 能沿 `tr.hist` 往回走。但 `computeBody`（`movement.ts:465`）每次都把 `hist` 裁到只剩车身覆盖的链，`recentBody` 也只保留 `hist` 里的链。车尾离后方链边界不到退行距离时，车尾要退回的那条链已经从 `hist`/`recentBody` 里删掉了，于是车身长度不够或「超出本车已占用路径」，永远不放行。现有测试（`tests/driver.test.ts` 'reverser is zero-speed only…'）是在同一条链里人为摆位，没覆盖跨链。

要求：
- 先用真实运行复现：海天三路上行（或任意车尾靠近链边界的站），人工驾驶真实开过标 1~5 m，打后、加牵引，记录 `reversePermission` 的返回。
- 修根因：车尾后方至少保留到「允许退行的最大距离」那么长的已走路径（≤5 m 司机自退，调度同意的更长退行也要覆盖），`hist` 和 `recentBody` 同一口径，只写一处。仍然只允许退回本车刚走过的轨道，其他检查（后方占用、进路锁闭、道岔原位）不放宽。
- 不让退的时候要说真话：把 `permit.detail` 显示在司机能看到的地方（DMI 消息或司机操作区），不能只是车不动。
- 用户补充：同一现场换向器打前、P4 也走不了（`movement.ts:820` 有 `tr.retreat` 时禁止向前牵引）。禁止向前本身对，但加上退行被拒就成了死局，司机和调度都没有出路。改成：退行权限被拒（不论原因）时，自动走现有的过标请示（`atoOverrun` 的 openCall，选项「同意退行对标」「越站」），让调度定；调度选越站后才放行向前。不另写一套请示。
- 回归测试：跨链的真实过标退行（≤5 m 自退、>5 m 调度同意后退）都能退回停车窗并开门；后方有车/进路锁闭时仍拒绝并显示原因。新字段按 AGENTS 坑 5 归类。

## 2. 没接管的 DTO/ATO 车也要显示站台近景（对标指示和发车倒计时）

现状：`src/ui/stopview.ts:177` 只在 `t.manual || t.atoDriver`（人工驾驶或 ATO 驾驶接管）时显示；`src/sim/engine.ts:766` 的 `platSide` 也是同样条件。用户在详情页看一列未接管的 DTO 车（020-1032 创新中路停站）时，近景和倒计时都没有。

要求：详情页选中的车，不管 DTO、AM、CM、是否接管，进站和停站时都显示站台近景、对标指示、发车倒计时（扣车 H 等照旧）。只改显示条件。注意 `platSide` 还被 `onboardaudio.ts` 用来定开门侧的声音：改条件不能让未接管车的车载声音行为变化，必要时把「近景用的侧别」和「声音用的侧别」分开。

## 3. CM 下给推荐速度（用户要求，参照 14 号线 DMI）

用户 2025-09-05 拍的 14 号线司机室（`work/line14-cab-2025-09-05.jpg`，不入库）：速度表外圈有三角标记，表下一行「实际：74　目标：72　最大：79」。

要求：
- CM 人工驾驶时，DMI 速度表外圈加一个推荐速度标记（黄色三角），表盘下方加一行「实际 / 推荐 / 最大」数字。最大 = 现有允许速度（红色弧线那个值）。
- 推荐速度 = 这列车如果是 ATO 驾驶此刻会追的目标速度：同一个 `vTarget` 计算，包括区间预算调速（D127，用同一个 ETA）、运行等级、限速和制动曲线、停车点。不要另写一套；现在人工驾驶车不进调速（`regulated` 为假），要把「算推荐」和「真正控制列车」分开，只让前者对人工车也算。
- 只加显示，不改人工驾驶车的实际运动；AM/DTO 下不显示这个标记（ATO 在开）。RM 不显示。
- 快照新增字段要同步到回放；不要让 UI 结果依赖上一帧。
- 帮助页（`src/ui/help.ts`）补一句推荐速度的含义。

## 4. DMI 的 DEP 和站台发车倒计时对不上

现场（用户截图）：071-1044 AM，远东大道上行停稳欠标 0.05 m，07:50:45 时 DMI 显示 DEP 07:50:59（还有 14 s），站台近景的发车计时器却已是红色超时计数。

原因：两处取了不同的「发车时刻」。`computeDmi`（`src/sim/dmi.ts` 约 100–105 行）的 `dep` 停站时用 `tr.dwellUntil`（ATS 实际给的发车时刻，晚到时按最短停站顺延）；`departureBoard.at`（同文件约 126 行）用的是任务里的图定 `current.dep`。车晚到时图定时刻已过，计时器就直接进入超时计数，而 DMI 还在倒数。

要求：发车时刻只算一处，DMI 的 DEP 和站台计时器都从它取。停站时以 ATS 实际发车时刻（`dwellUntil`，含扣车、调整）为准；进站前用这一站的计划发车时刻。超时红色计数仍从这个时刻起算。补测试：晚到的车，两处显示的秒数一致。

## 5. 停站中「恢复自动驾驶 → 切 CM」后，门已关、倒计时超时，P4 车不走

现场（用户截图，07:55）：071-1044 上行凌空路，DTO 进站停稳（欠标 0.06 m），用户先点恢复自动驾驶、再切人工驾驶 CM（DMI：07:54 ATPM模式可用 → DTO CBTC模式 → CM CBTC模式）。门已关，站台计时器红色超时 15，换向器前、手柄 P4，速度一直 0。DMI 目标距离显示「--m」；详情页当前任务已是「停站 川沙」，停车原因只写「人工驾驶 [MANUAL]」。

要求：
- 按这个顺序复现（AM/DTO 停站中切换模式，停站作业完成前后各试一次），找出是哪一条把牵引压成 0（`movement.ts` 约 820 行的门/换向器/retreat 条件、`pendingMode`、MA/目标距离、停站任务已出队但没给发车授权……），修根因。
- 停站中任何模式切换后，门锁闭、发车条件满足时，CM 司机加牵引就能走；条件不满足时停车原因写真实在等什么（AGENTS 坑 3），不能只写 MANUAL。
- 和第 1、4 项可能同源（退行状态、发车时刻、停站任务出队的口径），一起看，只改一处。
- 补测试：AM/DTO 停站中切 CM、CM 停站中切回自动再切 CM，都能正常发车。
