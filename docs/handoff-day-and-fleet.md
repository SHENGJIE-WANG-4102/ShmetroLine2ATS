# 任务：连续运行跨运营日不重开 + 车辆检修分工

两部分按顺序一次做完：先做第一部分，测试通过后接着做第二部分，中间不用停下来汇报。第二部分依赖第一部分（世界不重开，车号自然连续）。

---

## 第一部分：连续运行

### 背景

现在到 03:45 切换运营日时，`worker.ts` 调用 `start(nextOperatingConfig(sim))`，**整个仿真重建一遍**，只把各段的车数（`depotStock`）带过去。后果：
- 还在跑的车被收掉；
- 车场和正线存车位上的车号重新分配；
- 施工封锁、故障、进路全部丢失；
- 跨 03:45 的加开和夜间测试做不了。

**用户决定**：连续运行是最基本的要求。数据积累拖慢速度要靠清理旧数据解决，不能靠重开。

### 做法（已经调研过，按这个做）

`work/continuous-day-draft.patch` 是我按这个做法写的草稿：
- 约 440 行，类型检查通过，**没有跑过任何测试**；
- 可以参考，也可以直接用，但每一处都要你自己验证。

1. **每天仍用自己的时钟（04:00–27:45）。** 切换时把旧一天带过来的时间统一减 86400。
   - 只改数值 > 0 的有限时间；0、-1、∞ 这类「未设置」标记不动。
   - 为什么不改成连续时间：客流曲线、高峰时段、首末班、封锁窗口、运行图界面都按当天时刻写。改连续时间要动所有这些地方，漏一处就会出现第二天客流整天错之类的问题，而这只能靠长跑才发现。
2. **新的一天仍然由 `Sim` 构造函数生成**，加一个参数 `from`（旧的那一天），每天的初始化代码不复制第二份：
   - 新一天自己的部分：运行图、客流目标、随机故障、教员事件、节日、换乘衔接、当天统计；
   - 从旧一天带过来、并把时间减一天的部分：道岔、区段、信号、站台、ZC 状态、进路、股道预留、车场、故障、告警、无线电呼叫、天气、调度员计时、待复位的逆变器。
   - 把 `state.ts` 里 `CLONED`、`SCALARS` 的每个字段都明确分到「带过去」或「每天新建」。用一个覆盖全部键的 `Record` 让 TypeScript 检查有没有漏分，以后新加字段也逃不掉。
3. **列车**：
   - 先删掉构造函数自己生成的列车，再把旧列车搬过来。`removeTrain` 会清 `berthRes`、告警和呼叫，所以顺序反了会把旧的也删掉。
   - 还在跑的车：把它车底剩下的车次接到新运行图后面，换新的 id，时刻减一天，任务里的车次 id 一起换掉。
   - 停着没事的车：`block = -1`，等新一天的车底来领。
4. **正线存车出车**：改 `spawnStabled`。
   - 新一天从某个存车位出车的车底，先找停在那个位置的空闲车，用它出车（`standsAt` 判断位置，复用 `unfinishedAtRollover` 里比较车身中点的写法），车头朝向不对就换端。
   - 第一天没有这种车，照旧从 `stabledPool` 生成，所以第一天的结果不变。
   - 之后哪天存车位上没有车：记一条 B 级日志，不许凭空生成一辆车。
5. **施工封锁**：现在每天早上那 2 个封锁是随机抽的。改成：
   - 前一天晚上就把「明早封锁」排进计划（01:00–04:20，按新一天的时钟写）；
   - 切换时还在进行的封锁带到新一天，作为当天早上的封锁；
   - 封锁的 id 会重新编号，对应的无线电呼叫（`possReq`、`possRel` 的 `target`）和 `sec.poss` 要一起改。
6. **其他坑**：
   - `ActiveRoute.committed` 存的是列车 id，不是时间，不能减；
   - 告警的事件 id 要接着旧一天往下编，否则会重号；
   - 诊断：新一天的 `startState` 用切换那一刻的 `capture`，不能用 `new Sim(config)`，否则回放对不上；
   - `nextOperatingConfig` 的 `depotStock` = 车场里的车 + 正在回这个段路上的车；
   - worker 里切换改成调用 `rollover()`，不再调 `start()`：清空检查点和命令日志（回放不能跨天），然后发 `ready` 和 `dayChanged`；
   - 删掉 `planning.ts:116` 的「会被收掉」提示。`unfinishedAtRollover` 改成一条普通信息日志，列出跨天继续跑的车。
7. **数据增长**：切换本身就把前一天跑完的车次、事件、轨迹丢掉了，只带走还没跑完的。测试里要量一下，确认确实不增长。

## 第二部分：车辆检修分工

### 依据

| 项目 | 内容 | 来源 |
|---|---|---|
| 车场分工 | 川沙：停车场（停放、列检）；龙阳路：定修段（列检、月检/定修）；北翟路：车辆段（列检、月检/定修、架大修） | **用户决定**（依据配线图 V2025.26.2） |
| 列检 | 不超过 15 天 | 国家现行规定 |
| 月检 | 不超过 3 个月 | 国家现行规定 |
| 架修 | 02A05：5 年或 62.5 万 km；首批 23 列于 2025-02 至 2026-12 架修 | 02A05 架修招标公告 |
| 修程 | 上海地铁 2005 年前后改为**均衡修**：检修项目分散到每天停运后的几个小时里做 | 解放日报 2026-09-25 |

现状：工作日 118 个车底里，回原段 48 个，回别的段 55 个，从正线存车出或停回正线 15 个。工作日最多同时要 83 列车，100 列里富余 17 列。所以**只调整「哪辆车跑哪个车底」就能满足检修，不改运行图**。

【假设】
- 车只要在任何一个车场过夜，当晚就算做了列检；停在正线过夜的车不算。
- 月检计划周期 60 天，硬上限 90 天。做月检那天，车整天留在检修库。
- 北翟路同时有 1 列车在架大修（按首批 23 列、23 个月推算），一次 30 天。
- 检修库不占停车列位。

### 要做的

1. **数据**（`src/data/line2.ts`）：
   - 每个车场加能力字段 `work`；
   - `OPERATIONS` 里加检修规则：周期、上限、停用天数、同时架修几列；
   - 全部标【假设】并注明来源；代码里不许按车场名或车场 id 写判断。
2. **车辆档案**（`Sim.vehicles`，进存档）：
   - 记录上次列检日、上次月检日、累计里程（只用来显示）、当前状态（可用 / 月检中 / 架修中，含预计完成日）；
   - 第一天按种子把各车上次月检日均匀分布在 0–60 天前，并挑出架修车；
   - 旧存档里没有档案时，按种子补一份，不许报错。
3. **挑车规则**：只写一处，仿真和多天推演共用。
   - 收车回能做月检的段：优先派最急的车；
   - 收车回不能做月检的段：优先派最不急的车；
   - 收车停正线过夜：只派列检还有富余的车。
   - 超过硬上限、又只剩不回检修段的车底可派时：可以派，但要记日志写明车号和原因。
4. **每天切换时**：
   - 在车场过夜的车刷新列检日期；
   - 到期的车进检修库，前提是该段可用车不少于当天的 `yardNeed`。不够就推迟，并记日志；
   - 检修库里到期的车回到停车股道；
   - 按当天的挑车顺序重排各段股道（相当于夜间调车），让每股道最前面的车就是最先要出段的那辆。
5. **白天**：
   - `takeVehicle` 只从各股道最前面的车里挑，按同一套规则；
   - 回段的车要按它下一趟什么时候出段来选停哪股道（现在是停到最空的那股）；
   - 计划被打乱（退出服务、救援、加开、热备接替）时，也用同一套规则。
6. **界面和日志**：
   - 车场图单独列出检修库（例如「月检：0213」「架修：0102，预计 11-20 完成」）；
   - 车辆悬停显示上次列检、上次月检、累计里程；
   - 每天开局记一条「车辆运用」日志。

## 完成标准

1. 只运行一天时结果不变：两种日型运行图的 `trips`、`blocks` 哈希和改前一致，`validate-plan` 0 error，首末班脚本和改前一致。
2. 跨切换测试：从 26:30 开局，跑到第二天 05:30（约 3 小时仿真时间）。
   - 跨切换前后，列车 id、车号、位置连续；
   - 车场每股道的车号前后一致；
   - 27:30 发出的加开车跨过切换点后正常跑完；
   - 正线存车由前一晚停进去的那辆车出车；
   - 切换后深度扫描带过来的状态：不能有数值落在 12h–30h 之间、看起来是「忘了减一天」的时间字段。里程、坐标这类键列白名单排除。
3. 增长测试：不跑物理，连续调用切换 3 次，计划、事件、日志的规模不增长。
4. 检修多天推演（只用挑车规则，不跑物理）：
   - 连续 120 天，工作日、双休日按日历交替；
   - 每天按当天可用的车数生成计划（同样的日型和库存可以缓存）；
   - 没有车超过列检 15 天或月检 90 天，每天月检车数不超过富余；
   - 汇报贴出：每天月检车数的最大、最小、平均值，最长连续正线过夜的晚数，因库存不够改由别的段出车的趟数。
5. 存档：跨切换后存档再读档，状态一致；旧的单日存档能读。
6. `npx tsc --noEmit` 通过；`tests/operating-day.test.ts`（「会被收掉」和 `unfinishedAtRollover` 那几条按新行为改）、`tests/dispatcher.test.ts`、`tests/timetable.test.ts` 和新测试都通过。

## 不要做

- 不改运行图的生成规则和时刻，不加空驶，不改车场容量。
- 不靠重开仿真来解决任何问题。
- 推演发现富余不够时，不要调参数硬凑：停下来，把数字报给我。
- 不跑 `npm test`、soak、simday。多天长跑用户在 120× 下自己测。

## 用户在 120× 下看什么

- 23:00 后加开一列跑到 04:00 的车，看它跨过 03:45 后是否还在。
- 03:45 前后车场图的车号是否一致；检修库里有没有当天月检的车。
- 正线存车（蟠祥路、科技馆、浦东机场）第二天出车的车号，是不是前一晚停进去的那几辆。
- 连续跑几天，看速度有没有变慢。
