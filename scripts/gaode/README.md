# 高德到站时刻表采集

依赖 Python 3.10+（仅标准库）、Node.js / `npx tsx`（读取线路数据）、Android SDK Platform Tools 的 `adb`。
安装来源：[Android 官方下载页](https://developer.android.com/tools/releases/platform-tools)。
`adb` 可放 PATH，或用 `--adb 路径` 指定；也识别本仓库忽略目录
`work/gaode-tools/platform-tools/adb.exe`。

手机启用 USB 调试并允许这台电脑，打开高德的地铁 2 号线详情页。脚本只操作高德，
不会主动打开其他应用。导航坐标来自 UI XML 的 bounds；半屏详情页先拖动标题展开，
避免站名被底栏遮挡。时刻表方向按每行的「开往」文字复核。

采集器支持 `--line 14` 或环境变量 `ATS_LINE=14`，读取所选线路已有的官方首末班与端点；
其他线路批量采集时须用 `--station` 指定车站。当前日期仍须与 `--day` 的日型一致。
14 号线工作日车数对照运行 `$env:ATS_LINE='14'; npx tsx scripts/gaode-compare.ts`；
加 `--all-trips` 可查看不排除计划小交路的敏感性结果。具体证据、假设和局限见
`reference/line14/timetable-gaode.md`。

```powershell
# 检查连接；多设备时脚本加 --serial 设备序号
adb devices -l
# 自动切站，按任务优先级采集五站双向
python scripts/gaode/scrape.py batch
# 加上世纪大道、海天三路
python scripts/gaode/scrape.py batch --optional
# 中断后仅跳过今天已完成两次独立重入、一致且通过校验的表
python scripts/gaode/scrape.py batch --resume
# 只抓指定站 / 指定方向
python scripts/gaode/scrape.py batch --station 北新泾 --direction UP
# 指定站点双遍复抓；每遍都会退出时刻表并重新进入
python scripts/gaode/scrape.py capture --station 北新泾 --direction UP
# 查看当前时刻表文字（不打印背后的地图）
python scripts/gaode/scrape.py inspect
# 离线复核所有正式工作日文本并打印小时班次数及站间差异
python scripts/gaode/scrape.py validate
# 仅重建本页自动汇总区，不连接手机，不改原手录
python scripts/gaode/scrape.py summary
# 与重抓前留在 work/ 的文本基线逐分钟比较（新增、删除全部列出）
python scripts/gaode/scrape.py diff --baseline work/gaode-scrape/baseline-20261015
# 离线测试
python -m unittest discover -s scripts/gaode -p test_scrape.py
```

`UP` 往西、`DN` 往东，沿用 `src/data/current.ts`。东行全表最后一班与
`firstlast.ts` 中 `lastE`、`lastG` 较晚者比较。整分钟一致为通过；相差 1 min
保留明确提示；更大差异不覆盖正式文本。严格递增、去重、整小时缺失也自动检查。

每次滑动约 1/3 屏、保留重叠；遇到小时分组先点开；到屏幕连续两次不变才结束，
不会把「折叠小时列表没有新到站行」误判成到底。展开操作会让列表跳动，因此同屏
确认折叠的标题从下往上点；底边的单个标题不足以判折叠，先移动露出后续内容，
末小时须确认已到表底再处理。全部展开后从表底反向独立完整读取，
展开过程中读到的行不参与正式结果。每屏把完整行容器与到站 XML 节点逐行核对，
并记下各小时的条数。小时标题没有总班数数字，不能宣称已与页面总数对过。
边缘截断行用于相邻屏重叠；独立读取缺少重叠、标题缺失、重复节点、方向改变、
出现“展开更多”或行容器缺少到站文字时直接失败，旧正式文本保留。
已有展开分组从相邻的到站行识别，避免再点成折叠。
`batch` 和命令行 `capture` 对每站每向均从线路页重新进入两次；两次逐分钟、逐小时一致
才发布，不一致时证据留在 work/，正式文本不变。`--resume` 不再跳过仅通过首末班的旧表。
Python 接口 `capture()` 是单次读取，供既有调用方使用；双遍发布使用 `verified_capture()`。
`Device.connected()` 持有进程间手机会话锁，避免新采集进程同时切站；已在运行的旧版进程
无法补加这把锁，仍须按用户安排顺序使用手机。
每份通过的表自动更新 `reference/line2/timetable-gaode.md` 中带标记的汇总区，保留原手录
用于差异复核。每遍原始 XML、逐屏计数和诊断 JSON 写入已忽略的
`work/gaode-scrape/runs/<站点-方向-日型-时间>/`，不再只留最后一屏。
脚本本身不生成截图；排障截图也只能存 `work/` 并在完成后删除。

【假设】00–03 点归前一运营日，转写为 24:xx–27:xx，符合官方表次日时刻记法。
【假设】相邻已抓站同小时相差至少 5 班且超过较大班次数的 25% 时提示复查。
此项只是筛选提示，跨小时行车和区间始终发都会产生真实差异，不能据此补造车次。

`validate` 另做“夹心检查”：按线路顺序取同方向、同日类型的相邻三个采样站，
同小时中间站比两边各少至少 3 班就报警（包含恰好 3 班）。逐车检查复用
`match_trains.py` 的保序一对一配对，不能复用同一班车；打印两端都有而本站未匹配的
上游时刻、本站推定时刻、下游反推时刻及下游实测时刻。端点有同分多解、
本站附近有记录但配对容量不足时分别说明，不能当成已证实的漏行。

【假设】逐车时分用两站共同连续至少 5 班、恰好 5 分钟间隔的时间段取时差众数，
代表全天，容差 ±1 min；官方共同终点末班差 ±2 min 只用于约束相位窗口。
无共同样本或众数并列就明确提示无法估计，不回退造数；晚高峰时分可能不同，
缺车号时这些结果只用于挑选复查点。首班可能来自不同始发站，故这里不用首班差约束。

当前页面没有日期选择。星期一至五只能保存 `weekday`，周六日使用 `--day weekend`，
不能把工作日数据复制成周末表；法定节假日等特殊运行日需另核对运营安排。
本脚本面向已确认的 Android 手机。原生鸿蒙须另用 hdc 适配；不把 hdc/iPhone
当成 adb 设备。当前 UI 可完整读出文字，无须 OCR，也没有引入 OCR 兜底猜读。

## 东段补抓与逐车核验

```powershell
# 六站双向，先广兰路、金科路、远东大道；手机须独占
python scripts/gaode/capture_east.py --resume
# 研究用途：仅首末偏差2min、双遍逐分钟一致时，保留显式标记的实读观测
python scripts/gaode/capture_east.py --resume --keep-endpoint-observation
# 离线分析全部八个采样站，不连手机；明细在忽略目录
python scripts/gaode/east_analysis.py --output work/gaode-east-analysis
python -m unittest discover -s scripts/gaode -p 'test_*.py'
```

`capture_east.py` 复用原采集器的行解析、重叠、小时完整性和首末班校验。
回卷、展开和正式读取按 XML 行高计算距离、目标保留3行重叠，
再用重叠行实际位移修正下一滑；拖动时长随距离增加，限制手指速度以免甩动，
停稳后读取；从下往上展开同屏的折叠标题，
不能把“标题贴在视口底部，看不到首行”误当成折叠。展开后先从底读到顶，再从顶读到底，
两遍逐分钟、小时分组、方向标签完全一致才发布，文件头明确写“同页完整复读”。
此法和 `scrape.py batch` 的“两次重新进入”有区别，不互相冒充。
每屏 XML 和诊断留 `work/gaode-scrape/`，不生成截图；导航还会实际点击列表站名，
避免把线路页的“开往广兰路”目的地误认为当前选中了广兰路。

广兰路东行上车表末班应校验 `lastE=23:00`；该站 `lastG=23:44` 是终到到达，
到站后不能继续往东上车。广兰路以西的各站仍取 `lastE/lastG` 较晚者，
保留晚间终到广兰路的载客车，不改官方首末班源文件。

默认仍拒绝首末偏差超过1 min的表。`--keep-endpoint-observation` 仅允许首末偏差
不超过2 min且双遍完全一致的实读样本，文件头写“首末班状态：未通过”，并保留实际
时刻和偏差；不补造官方时刻、不降低 `scrape.py validate` 的标准。重复、空表、缺小时、
无重叠、较大偏差仍拒绝。东段分析只对带此明确标记的小偏差观测保留警告后计算，
不能当作官方首末班校准通过。

`east_analysis.py` 复用 `match_trains.py` 的保序、一对一、最大匹配数优先、
总误差次优的动态规划。东段估时用全表候选时差众数，搜索窗为同终点官方末班差
±2 min，逐车容差 ±1 min；有并列众数时明确保留全部众数，择离锚最近者仅供生成
一个候选解。它与西段分析器取“共同连续5分钟段”的样本选择不同，报告中保留直方图。
另以原脚本的5分钟段方法作参考，保存其估值或无法估计的原因；涉及唐镇的四个采样段
本批没有共同干净5分钟段，所以不能将全表众数冒称为该方法的已验证估值。

输出 `edges.csv`（每条边的择一配对及同分候选）、`paths.csv`（每条完整/残缺路径）、
`hourly.csv`（每站每向逐小时分类，和严格等于原表）、`aligned-hourly.csv`（下游窗平移
后的班次数）、`turns.csv`（折返候选）、`depot-candidates.csv`（远东大道门户候选）和
带源文件 SHA-256 的 `report.json`。默认都放 `work/`，可离线重算。

“贯通”只表示八个采样站全部连上（张江高科—海天三路），不等于已识别全线车号。
其余分东段候选、核心段候选、远东大道出入段候选及未定碎段；单个到站点始终为未定。
出现/消失指采样表边界，不自动等同真实始发/终到；川沙停车场接轨在远东大道，
川沙站的消失记录不自动算入段。最东端无机场表，不把海天三路边界认作折返点。

【假设】折返最低2 min、最长12 min；另给最低4/6 min、最长8/20 min敏感性，不能将模型最短折返值
当作现实认证参数。另检验单折返站台、前车开出至后车到达留0/1 min的数量上限，不能只看时刻能配。
广兰路、创新中路分别检验“本站实测到发”、“终到不刊载，按众数
推算到达”和“始终发均不刊载，两端均由相邻采样站推算”三种替代口径；各口径不能
相加，也不能用时间能配对就宣称同一车底。结论及置信度见 `reference/line2/timetable-gaode.md`。

若广兰路—创新中路的始终发都不刊载，短交路中间只剩唐镇一个采样点。
唐镇单点在总分类中仍属未定，仅在上述明确的端点未刊载假设中纳入折返检验，
报告另列使用了多少单点；川沙单点因含车辆段/凌空路歧义不照搬此规则。
`report.json` 的 `short_shuttle_hypothesis` 还把同组唐镇单点在两端的单线折返接成往返链，
检验最低2/4/6 min的敏感性；12 min等待上限会截断长停，链数不是实际车队规模。
创新中路中间线无站台，载客到发需要额外调车；时间配对仅是必要条件。
广兰路的单线检验未扣除核心段小交路占用，所报数量是候选方案上限。
